# Сайт проекта по определению кортизола

Готовый статический проект на HTML, CSS и JavaScript, без сборки, библиотек, внешних шрифтов и серверной части. Сайт не опубликован.

## Дизайн и структура

Белый и серо-голубой фон, тёмно-синий #163e49, бирюзовый #247a77. Системный шрифт Arial/Helvetica. Ширина контента до 1280 px, сетки перестраиваются на 1100, 800 и 540 px. Крупная типографика, тонкие границы, скругления 6–16 px. Схематичная SVG-иллюстрация подписана как концепция, не как реальный прототип.

- index.html — семантические разделы, контент, SEO, места под логотипы и скриншот.
- style.css — дизайн-система, мобильная навигация, адаптивность, reduced motion.
- script.js — PROJECT_NAME, CONTACT_EMAIL, меню, анимации и подготовка письма.
- assets/test-concept.svg — заменяемая иллюстрация.
- assets/favicon.svg — временный знак проекта.
- .nojekyll — отключение обработки Jekyll на GitHub Pages.

## Локальный запуск

Можно открыть index.html двойным щелчком. Для проверки в условиях HTTP откройте терминал в папке проекта:

```sh
python3 -m http.server 8000
```

Откройте http://localhost:8000. Остановить сервер: Ctrl+C. Node.js и установка зависимостей не нужны.

## Публикация на GitHub Pages

1. Создайте репозиторий в своём GitHub-аккаунте.
2. Загрузите **содержимое** этой папки в корень ветки main: index.html должен находиться в корне, а не внутри cortisol-site.
3. Откройте Settings → Pages → Build and deployment → Deploy from a branch.
4. Выберите main и /(root), сохраните.
5. Дождитесь успешного развёртывания и откройте адрес, показанный GitHub Pages.

Все локальные ссылки относительные: проект подходит и для https://USER.github.io/REPOSITORY/. Не заменяйте пути assets/... на /assets/..., иначе они будут указывать в корень домена.

## Что заменить до публикации

1. `PROJECT_NAME` в script.js. Замените также исходные вхождения «Название проекта» в index.html, включая title, чтобы название отображалось без JavaScript и корректно индексировалось.
2. `CONTACT_EMAIL` в script.js — реальный email Виктории, например `const CONTACT_EMAIL = 'real-address@example.org';`. Не используйте пример как настоящий адрес. Пока значение пустое, кнопка формы отключена. Адрес автоматически появится в контактах и подвале.
3. Официальные логотипы — по инструкции ниже. Сейчас на сайте честно подписанные текстовые места, не имитации логотипов.
4. Реальная фотография прототипа и скриншот анализатора — по мере появления.
5. Подтверждённые характеристики — четыре карточки .specs в index.html. До подтверждения оставьте «Уточняется».
6. После получения публичного адреса добавьте в head канонический адрес и og:url с абсолютным HTTPS URL сайта. При наличии реального изображения для социальных сетей добавьте og:image с абсолютным URL PNG/JPEG и og:image:alt. Базовые Open Graph title, description, type, locale уже есть; картинка намеренно не выдумана.

## Изображения и официальные логотипы

Получите утверждённые исходники ФСИ и Платформы из материалов, применимых к вашему договору. Сохраните их как assets/fsi-logo.svg и assets/platform-logo.svg (или PNG, изменив расширение в HTML). Не изменяйте цвета, пропорции и защитные поля.

Замените содержимое блоков #fsi-logo и #platform-logo соответственно:

```html
<img src="assets/fsi-logo.svg" alt="Фонд содействия инновациям" loading="lazy">
<img src="assets/platform-logo.svg" alt="Платформа университетского технологического предпринимательства" loading="lazy">
```

Каждый img должен находиться в своём блоке. При необходимости увеличьте блок под охранное поле согласно брендбуку. Текущие подписи о местах для файлов после замены удалите.

Для реального скриншота сохраните assets/analyzer-screenshot.png и замените содержимое figure#app-screenshot:

```html
<img src="assets/analyzer-screenshot.png" alt="Реальный интерфейс приложения для анализа теста" loading="lazy">
```

Для фото прототипа замените src, размеры и alt у изображения в .hero-art и обновите подпись. Иллюстрация test-concept.svg не описывает окончательную конструкцию и расположение зон теста.

## Контактная форма

Используется mailto. Форма проверяет обязательные поля и формат email, затем передаёт имя, адрес для ответа и сообщение почтовому приложению посетителя. Отправку подтверждает сам посетитель. Сайт не показывает успешную доставку и не сохраняет введённые данные. Если почтовый клиент не настроен, можно скопировать видимый контактный email. Длинные письма могут ограничиваться почтовым клиентом; для вложений используйте сам клиент. Платных сервисов, API-ключей и бэкенда нет.

## Проверки и ограничения

Проверены синтаксис JavaScript, наличие локальных ресурсов, ссылки-якоря, уникальность id, ссылка анализатора и дословный текст поддержки. В CSS предусмотрены мобильные сетки и prefers-reduced-motion.

Визуальная проверка на мобильном экране, работа в Safari/Chrome/Firefox и отсутствие ошибок в браузерной консоли **не подтверждены**: локальный HTTP-сервер заблокирован средой, открытие file:// отклонено политикой браузера. Не подменяйте эту запись утверждением об успешном браузерном тесте. Сам внешний анализатор не изменялся; его доступность веб-инструментом проверить не удалось.
